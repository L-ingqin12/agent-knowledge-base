# 操作系统八股

> [!abstract] 定位
> 面试与工程双用的 OS 主干：进程线程调度、虚拟内存、中断与系统调用、锁实现、IO 多路复用。Linux/Windows 双轨标注；实践侧对接 [[高并发系统设计]] 与 [[log-analysis-agent-windows-architecture]]。

See also: [[CS-KB-Home]] · [[计算机网络八股]] · [[高并发系统设计]] · [[CPP-核心知识]]

## 一、进程 / 线程 / 协程

| 维度 | 进程 | 线程 | 协程 |
|------|------|------|------|
| 地址空间 | 独立 | 共享进程空间 | 同线程内用户态切换 |
| 切换成本 | 页表切换 + TLB 影响（PCID 前=CR3 写即全刷；PCID 机器免整表刷新）；真正贵的是跨地址空间 TLB 影响 + cache 冷启动/调度器开销 | 内核态上下文保存 | 栈帧保存，纳秒级 |
| 通信 | IPC（管道/共享内存/socket） | 直接共享+同步原语 | 语言级 channel/await |
| 崩溃隔离 | 强 | 一损俱损 | 同左 |

> [!warning] 更正（2026-09-13）：进程切换并不必然"全刷 TLB"——PCID 允许在换页表（CR3 写入）时跳过整表 TLB 刷新；INVPCID 可只失效**非当前 PCID** 的条目，不支持 INVPCID 的机器只能失效当前 PCID；PTI 场景下 global page 被禁用的开销，内核文档给出量级「never exceeding 1%」。真正的"最贵"落在跨地址空间的 TLB 影响 + cache 冷启动 + 调度器开销这些间接成本上。（原表述为「页表切换+TLB 刷新（最贵）」，属 PCID 普及前的模型）
> 来源：https://docs.kernel.org/arch/x86/pti.html

- **fork vs vfork vs posix_spawn**：COW 使 fork 便宜；exec 后 COW 白拷 → spawn 更优
- **僵尸/孤儿**：子进程终止后父进程须 `wait()` 收尸，否则僵尸占 PID；孤儿被 init/systemd 收养
- Windows 差异：无 fork；CreateProcess 全新映像；线程是调度唯一单位（进程仅容器）

## 二、调度

- Linux CFS：vruntime 红黑树选最左侧；nice 权重→时间片比例；EEVDF（6.6+ 取代 CFS，按虚拟截止期，~~细节待确认~~ 已补齐，见下）
  - EEVDF 规则：筛出 lag≥0 的 **eligible** 任务，各自算虚拟截止期(VD)，取 VD 最早者运行；睡眠任务用虚拟运行时间做 lag decay——防止"短睡一下重置负 lag"的套利
  - 延迟敏感任务可用 `sched_setattr()` 申请指定时间片
  - CFS 侧口径已改口为「Nowadays, CFS is making room for EEVDF」：CFS 用纳秒级记账、不依赖 jiffies/HZ，因而**没有时间片概念**；唯一中央调优旋钮是 `/sys/kernel/debug/sched/base_slice_ns`
  > 来源：https://docs.kernel.org/scheduler/sched-eevdf.html · https://docs.kernel.org/scheduler/sched-design-CFS.html
- 实时策略：SCHED_FIFO/RR 优先级抢占
- Windows：32 级优先级 + 量子；前台提升

## 三、虚拟内存

```
VA ──页表(多级)──▶ PA    TLB 缓存映射；缺页中断换入
```

- **页面置换**：LRU 近似=时钟算法（访问位）；Linux 分 active/inactive 双链 + kswapd 后台回收
- OOM：内存压力下 oom_score 选杀；容器内 cgroup limit 触发 OOM kill（`137` 退出码经典案发）
- **压力观测(PSI)**：`/proc/pressure/{cpu,memory,io}` 各含 `some`/`full` 两行 + avg10/avg60/avg300 与 total——`some`=至少部分任务被拖住的时间占比，`full`=所有非空闲任务都被拖住；cgroup2 下每层另有 `cpu.pressure`/`memory.pressure`/`io.pressure`，支持写入阈值后用 `poll()+POLLPRI` 等事件
  - 工程含义：判断"快 OOM 了"先看 PSI；`oom_score`/`oom_score_adj` 只决定**杀谁**——两套机制不可互相替代
  > 来源：https://docs.kernel.org/accounting/psi.html
- mmap：文件映射免 read 拷贝；匿名映射=malloc 大块底层；写时复制支撑 fork
- **零拷贝族**：sendfile/splice 绕过用户态；对应网络发送路径见 [[计算机网络八股]]

## 四、锁的层级实现

| 层级 | 实现 | 要点 |
|------|------|------|
| 用户态自旋 | atomic CAS | 临界区极短；忙等烧 CPU |
| futex(Linux) | 快路径用户态 / 冲突陷入内核休眠 | mutex 底座 |
| 读写锁 | shared_mutex / RCU(读免锁) | 读多写少；RCU 写者复制-指针切换 |
| 死锁四条件 | 互斥/持有等待/不可剥夺/循环 | 破环：全局锁序或 try_lock 回退 |

内存屏障与 acquire/release 对应 CPU 重排——与 [[CPP-核心知识]] §四同源。

## 五、IO 路径演进

| 模型 | 机制 | 复杂度 |
|------|------|--------|
| 阻塞+多线程 | 一连接一线程 | C10K 天花板 |
| select/poll | fd 数组轮询 | O(n) 每次全量拷贝 |
| **epoll** | 红黑树注册+就绪链表回调 | O(1) 就绪通知；ET 边沿触发需非阻塞读空 |
| io_uring | 提交/完成双环形队列共享内存 | 批量异步，系统调用趋零 |
| Windows IOCP | 完成端口重叠 IO | 生产者消费者完成队列 |

### 附：io_uring 能力 × 最低内核版本（据 man 手册逐项标注）
| 能力 | 最低内核版本 | 说明 |
|------|------------|------|
| io_uring 本体（`io_uring_setup`）+ 初始能力面（含 SQPOLL） | 5.1 | 提交环/完成环共享内存 + 系统调用入口，即原表述的"5.1 引入" |
| SQPOLL 免注册文件即可用 | 5.11 | 手册原文「In version 5.11 and later, it is no longer necessary to register files to use this feature」 |
| SQPOLL 非 root 可用 | 5.11（需 `CAP_SYS_NICE`）→ 5.13 起要求放宽 | 能力位 `IORING_FEAT_SQPOLL_NONFIXED` |
| multishot 等后续能力 | 5.10 / 5.18 / 5.19 / 6.18 等分项标注 | 手册按项标「Available since …」，须逐项查 `io_uring_setup(2)`；不要用"5.15+ vs 6.x"这类粗粒度问法 |

> 来源：https://man7.org/linux/man-pages/man2/io_uring_setup.2.html · https://man7.org/linux/man-pages/man7/io_uring.7.html

## 六、机制深讲四则（从"是什么"到"为什么"）

### 1. epoll LT vs ET——语义级差异与代码契约
- **LT(默认)**：只要就绪条件持续，每次 epoll_wait 都返回该 fd → 编程宽容：读到 EAGAIN 为止不是必须
- **ET**：仅在状态**变化沿**通知一次 → 必须一次性把缓冲区抽干（`while(recv()>0 || errno==EAGAIN)` 循环），且必须非阻塞 fd，否则一读阻塞拖垮整个事件循环
- 选择：库封装(nginx/muduo)用 ET+统一抽干循环榨性能；简单服务 LT 少踩坑
- **惊群**：多进程/线程共享同一 listen fd 时 accept 惊醒多个 → EPOLLEXCLUSIVE(内核 4.5+) 或 SO_REUSEPORT 各自独立队列按哈希分流
  - `EPOLLEXCLUSIVE` 的四条使用契约（man 手册逐条）：只能在 `EPOLL_CTL_ADD` 时使用，配 `EPOLL_CTL_MOD` 直接报错；events 里混用其它标志位返回 `EINVAL`；目标 fd 本身是 epoll 实例时同样 `EINVAL`
  - 同一 fd 同时挂在"带该 flag"与"不带该 flag"的 epoll 实例上时，唤醒语义会退化——写惊群 demo 卡在 EINVAL 多因上面几条
  > 来源：https://man7.org/linux/man-pages/man2/epoll_ctl.2.html

### 2. 缺页三类型（调优视角）
| 类型 | 触发 | 成本 | 处置 |
|------|------|------|------|
| minor(软) | 页在 page cache/已分配未映射 | µs 级建映射 | 预热(mlock/touch) |
| major(硬) | 需从 swap/文件回读 | ms 级 IO | 内存加量/禁换关键进程 |
| COW/fork 后写 | 写时复制触发真实分配 | 中 | 高频 fork 服务改 vfork/spawn 思路 |

`ps -o majflt/minflt` 区分观察——majflt 高=内存不足或映射文件冷。

### 3. 零拷贝三方案对比
| 方案 | 路径 | 适用 |
|------|------|------|
| mmap+write | 文件映射进用户态再写 socket | 可对数据二次加工 |
| **sendfile**(含 DMA gather) | 文件→socket 全内核态, CPU 零参与拷贝 | 静态文件分发(Kafka/nginx 主力) |
| splice | 管道中转的零拷贝搬移 | 管道两端流式拼接 |

共同前提：数据不需要在用户态被"看"一眼——需要 TLS 加密时路径回到用户态(kTLS 才恢复纯内核)。

### 4. 调度器演进动机链
O(n)(2.4：每调度扫全进程表,扩展性差) → **O(1)**(2.6：优先级位图+每CPU双队列,但交互启发式复杂难维护) → **CFS**(vruntime 红黑树,"公平"替代"启发") → **EEVDF**(6.6: 公平+延迟敏感,虚拟截止期让低延迟任务可表达诉求——它不是在"时间片轮转"上打补丁,而是把 CFS 的"公平"换成对延迟的显式表达)。每代都在解上一代的真实痛点——面试答演进比答名词高一档。
