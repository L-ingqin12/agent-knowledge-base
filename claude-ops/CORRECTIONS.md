# CORRECTIONS — 错误记忆库

See also: [[AGENTS]] | [[HOME]] | [[Claude-Ops-KB-Home]] | [[URL-Lookup]] | [[agent-memory-context-knowledge-design]]

> [!abstract] 这个文档是什么
> **可检索的方法论错误记忆库**。记录的不是「知识」，而是**做过的错误判断、错在哪一步、以及可复用的判定规则**。
>
> 为什么单独建库：本库已有 [[MEMORY-INDEX]]（架构模式记忆）与 31 处散落的「教训」小节，但**没有一处专门记录「我判断错过的结论」**。错误散落在正文里 = 不可检索 = 必然重犯。
>
> 分层定位：按 [[agent-memory-context-knowledge-design]] 的三级模型，本库属 **L3 长期记忆**。**只把触发规则放进提示词，正文留在本文件**——该文档明确警告「把长期知识硬编码进系统提示词是最高频反模式」。

> [!danger] 录入门槛（不记琐碎错误）
> 只有满足以下**至少一项**才录入：
> 1. 错误**已输出给用户或写入交付物**，可能被当真
> 2. 错误属于**可复现的推理模式**，换个场景还会再犯
> 3. 错误**推翻了一个原本正确或原本错误的结论**，导致结论反复
>
> 拼写、笔误、一次性疏漏不录。

## 速查索引（按「什么时候要回忆」检索）

| 当你准备… | 警戒 | 条目 |
|---|---|---|
| 判定某版本「是否受某漏洞影响」 | 只读了「受影响范围」，**必须同时读「修复版本」** | [[#C-001 只读漏洞公告的一半]] |
| 把「开放端口 / 可达 / 存有凭据」写成风险 | **可达 ≠ 可被利用**；先确认认证方式与凭据强度 | [[#C-002 把可达性外推为可被利用]] |
| 用脚本或工具扫一遍就下「干净」结论 | **扫描器可能是瞎的**；先验证扫描本身有效 | [[#C-003 信任未经校准的扫描结果]] |
| 引用他人（含子代理）的结论 | 对照原始来源复核，尤其**结论数字与计数** | [[#C-004 转述未回溯原始来源]] |

> [!tip] 一句话总纲
> 本库 4 条错误（截至 2026-09-12）**全部属同一根源**：**把「观察到的现象」直接当成「结论」**。
> 现象 → 需要一步判定 → 才能成为结论。**漏掉中间那一步，就是这四条。**

## C-001 只读漏洞公告的一半

| 项 | 内容 |
|---|---|
| 发生 | 2026-09-12 |
| 场景 | 核对 `path-to-regexp` 8.4.2 是否受 CVE-2026-4926 影响 |
| 我的错误结论 | 「该版本受影响，且**无补丁可用**」→ 据此判定子代理「漏报一条高危」 |
| 事实 | 公告同页写着 `Patched version: >= 8.4.0`；8.4.2 **已修复**。Debian 与 Ubuntu 追踪库均确认 `Fixed in version 8.4.0` |
| 错在哪一步 | 读了 `Affected versions: >= 8.0.0` 就停止阅读，**没读紧随其后的下一行** |
| 可复用规则 | **判定受影响 = `已装版本 ∈ 受影响范围` 且 `已装版本 < 修复版本`。两个值缺一不可。** |
| 检测方法 | 写完任何漏洞判定，自查：「我引用的修复版本号是多少？从哪一行读到的？」答不出即无效 |
| 波及 | 向用户输出过两次相反结论；已更正并保留记录 |

> [!bug] 加重情节
> 我不仅自己判错，还**推翻了子代理原本正确的结论**。复核他人结论时，若自己的复核依据不完整，会把「对的改成错的」。

## C-002 把可达性外推为可被利用

| 项 | 内容 |
|---|---|
| 发生 | 2026-09-12 |
| 场景 | 检视本机 MobaXterm 会话记录，发现 4 个公网 IP 的 `root` SSH 会话 |
| 我的错误结论 | 报为**严重项「S8」**：3 台公网主机 22 端口可达 + root 直登 + 凭据存于无主密码的 MobaXterm |
| 事实 | 用户确认**密钥认证、无口令复用**；复检 `MobaXterm.ini` **无任何口令字段**，其私钥目录**无私钥文件**。原判断不成立，已撤回 |
| 错在哪一步 | 三步缺失：① 只测了 TCP 可达，**没验证认证方式**；② 把「21 条会话」误读为「21 条口令」（实际是会话元数据）；③ **没先问所有者**就列入严重项 |
| 可复用规则 | **判定暴露面必须落到三个具体问题：认证方式是什么？凭据强度如何？是否复用？** 三者缺一，就只是「观察」而非「判断」 |
| 补充 | 「公网开放 22 + 使用 root」是**常规配置**，不是缺陷。`root` 是标准用户名，不泄露信息 |
| 元教训 | 过度定级会**稀释真正严重项的可信度**——把常规配置报成严重，读者会开始怀疑整份报告 |

> [!quote] 用户的纠正是对的
> 「root 登录应该本身不构成威胁吧，除非别人入侵了我的电脑」——这个推理链成立。**root 直登 vs 普通用户 + sudo 的风险差异很小**（拿到任一账户后 `sudo bash` 一行即达），业界主张禁用主要为**可审计性**，非漏洞。

## C-003 信任未经校准的扫描结果

| 项 | 内容 |
|---|---|
| 发生 | 2026-09-12 |
| 场景 | 审计 `~/.dsh/profiles/node_modules` |
| 风险 | 该路径是 **256 个 junction 的农场**，`Get-ChildItem -Recurse` 与 `rg`/`grep` **都不跟随 junction** |
| 实测 | `-Recurse -File` 返回 **0 个文件**（而目录有 628 个） |
| 后果（若未发现） | 任何密钥扫描/依赖审计都会返回「0 命中」，并**被误读为「干净」** |
| 可复用规则 | **下「未发现」结论前，先证明扫描器看得见目标。** 用一个已知存在的样本做阳性对照 |
| 检测方法 | 扫描后问：「我期望至少命中几条？没有命中是好事还是扫描器瞎了？」 |
| 延伸 | 同理适用于：`.gitignore` 排除、权限不足导致的静默跳过、大小写/编码差异 |

## C-004 转述未回溯原始来源

| 项 | 内容 |
|---|---|
| 发生 | 2026-09-12 |
| 场景 | 采纳子代理的依赖 CVE 审计结论 |
| 现象 | 子代理把 `ws` 的 **CVE-2026-48779 与 GHSA-96hv-2xvq-fx4p 列为两条不同公告**，实际**是同一个**（GHSA 是 GitHub 侧编号，CVE 是通用编号） |
| 另一现象 | 子代理只查了它自己列出的 CVE 编号，**没有反向核对上游项目的官方安全公告**（Express blog 同批就披露了 3 条 CVE） |
| 可复用规则 | 采纳转述结论时：① **核对计数**（「2 条」是不是真的是 2 条不同的事）；② **回溯到项目官方来源**，不只依赖聚合站编号列表 |
| 边界 | 这不意味着不要用子代理——而是**转述必须留下可回溯的原始链接** |

> [!note] 与源码的关系
> 本条不是「子代理不可信」，而是「**转述衰减**」：每经一手，计数与范围都可能漂移。同一份报告里，我也犯了 C-001（自己判错）。

## 录入协议

新增条目时：

1. **编号**：`C-00N`，递增，**不复用已撤回条目的编号**
2. **必填六项**：发生时间 / 场景 / 我的错误结论 / 事实 / 错在哪一步 / 可复用规则
3. **必须写「检测方法」**——没有可执行的检出手段，这条记忆就无法在下次生效
4. **同步更新速查索引**（表格首行），否则等于没录
5. **不改写已录条目**——若某条后来被推翻，新增一条并回链，而不是修改原文（保留「我错过」这个事实本身）
6. **撤回的结论也要录**（如 [[#C-002 把可达性外推为可被利用]]）——**撤回比错误本身更有价值**，因为它标出了哪类推理会产出假阳性

> [!warning] 本库自身的失败模式
> 错误记忆库最危险的失败不是记错，而是**记了却没人查**。
> 因此：任何结论在被写入交付物前，应回查本库速查索引一次；发现命中即按对应规则重检。
> 该触发规则已写入 [[AGENTS]]，使新会话的 Agent 能载入本库。
