执行上线前全面检查工作流。

## 步骤 (并行 Fan-Out)

同时委托以下三个子智能体：

1. **code-reviewer** — 审查 $ARGUMENTS 中指定目录（或默认 src/）的全部代码
   关注：错误处理、边界条件、API 接口变更、代码风格一致性

2. **security-auditor** — 对相同范围做 OWASP Top 10 安全扫描
   关注：注入漏洞、认证失效、敏感数据暴露、依赖 CVE

3. **doc-writer** — 检查并更新 README 和 API 文档
   关注：新增的 API 端点、配置变更、架构变化

## 质量门控

每个子智能体输出必须通过：
- 审查/审计类: 有具体文件:行号引用 + 可操作的修复建议
- 文档类: 内容充足（非空）

不通过则携带反馈重试，上限 3 次。

## 输出

汇总三个子智能体结果，交叉验证（同一问题被多个子智能体报告 → 升级为严重），
按优先级排序汇报：🔴 阻塞上线 → 🟡 建议修复 → 🟢 已完成
