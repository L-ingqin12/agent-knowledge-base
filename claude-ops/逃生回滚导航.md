# 逃生/回滚导航（Escape & Rollback MOC）

> [!abstract] 本页用途
> 「系统出问题，该怎么逃生 / 怎么回滚」的入口导航。覆盖 permafrost 缓存链、cache-relay / DeepSeek-400 / 分类器 / 天枢、Claude Code 版本切换，以及事故复盘沉淀的经验。
> 相关：[[Claude-Ops-KB-Home]] · 脚本实体根目录 `D:\Document\local\knowledge\scripts\claude-ops-deployments\`（`root-scripts/`、`cache-relay/`、`cc-version-switch/` 等，均带 deploy / rollback）。

## 一、一句话：逃生 ≠ 回滚

> [!important] 最核心的一句
> **逃生 = 快速止血**（逐层关闭可疑的层/补丁/开关，系统保持运行，低代价、可随时恢复）；**回滚 = 恢复到已知好状态**（还原快照 / git revert / 切回直连，代价较高，一般逃生用尽才用）。**每次逃生只退一层。**

| | 逃生 Escape | 回滚 Rollback |
|---|---|---|
| 目的 | 先让链路恢复可用 | 回到已知好状态 / 基线 |
| 手法 | 逐层关 feature、写 `.disabled`、`passthrough`、disable hook | `git revert` / `git reset` / 还原快照 / 切直连 |
| 关键词 | L0m/L0a/L0b · E0 · F0 · disable | L1–L4 · R0 · rollback · nuke |
| 是否动配置 | 尽量不动，只拨运行开关 | 会动 settings / env / 文件 |
| 代价 / 可逆 | 低，随时能回来 | 高，可能丢缓存 / 丢优化 |

设计原则（各 doc 反复强调）：逃生与回滚**必须与功能同步设计**；软回滚优先、**禁止硬删除脚本**；每次改动前先 `cp` / commit 快照。

权威定义在**脚本头部注释**，不在 .md 文档里。核心拓扑：方案 C = CC→permafrost→proxy→上游；方案 B = CC→permafrost→上游直连；直连 = CC→上游。

| 场景 | 看哪篇 | 一句话要点 | 关键命令 / 路径 |
|---|---|---|---|
| 七级通道权威用法 | **脚本本体**（唯一权威） | 每级只退一层；L0 补丁级、L1–L4 结构级 | `scripts/claude-ops-deployments/root-scripts/claude-permafrost-rollback.sh` |

| 补丁改动与恢复记录 | [[PERMAFROST_MODIFICATIONS]] | 补丁权威放 repo patches/；`.orig` 须在补丁成功后更新 | `deploy.sh rollback && deploy.sh start` |
| 缓存优化整体架构 | [[claude-resilience-architecture]] | 方案 B↔C 切换命令与逃生通道位置 | `claude-permafrost-deploy.sh {start · rollback · stop · status}` |

| 日常 cache 维护命令出处 | [[claude-cache-optimization]] · [[claude-cache-strategy]] | 方案切换与版本切换命令的引用源头 | `permafrost-deploy.sh rollback` · `version-switch.sh rollback` |

L0 / L1–L4 一句话速记（来自 rollback.sh 用法行）：

| 级别 | 命令 | 动作 |
|---|---|---|
| L0m | `model-off` | 关 model 路由（保留 tools / currentDate） |
| L0a | `tools-off` | 关 tools 重排（保留 currentDate） |
| L0b | `patches-off` | 还原 `.orig` → 全部补丁关（回到原版 permafrost） |
| L1 | （默认） | 方案 C→B：permafrost 绕过 proxy、保留缓存优化 |
| L2 | `full` | B→直连：绕过 permafrost、无缓存优化 |
| L3 | `disable` | 禁用 auto-deploy hook |
| L4 | `nuke` | 完全清零（等价 `claude-rollback.sh`） |

## 八、最容易踩的坑

1. **把「逃生」当「回滚」**：一上来就 `nuke` / `full`，缓存优化全丢；应先逐层 L0m → L0a → L0b → L1 → L2。
2. **级数定义看错文档**：06-13 复盘的「四级 L1–L4」是旧定义；七级（补丁级 L0m/L0a/L0b + 结构级 L1–L4）以 `rollback.sh` 头注释为准。
3. **`.orig` 备份陷阱**：`.orig` 若停在「原版」，恢复操作会把所有补丁清零——补丁成功后要 `cp` 更新 `.orig`。
4. **硬删除脚本**：软回滚域禁 `rm`；一律走 `.disabled` / env 开关，删了丢版本历史、无法一键恢复。
5. **改动前不存快照**：没有回滚门禁就没有回滚；每次部署前先 `cp` 备份 / commit。
6. **逃生通道本身没验证**：部署脚本端口竞态曾让 L1 逃生失败；逃生通道要在部署前就绪并实测。
7. **走错相邻文档**：会话中断 / 任务续接是「恢复」（[[claude-interruption-resilience-guide]] / [[claude-context-continuity-guide]]），不是逃生；在本导航找不到答案。

## 十、逃生成功判据（逐域自证）

§一–§九 讲「怎么逃生」，但没有一条能自证「**已经逃成功**」。下表按域给出可执行验证——**判据不成立就说明还没恢复，不要接着做下一步**。

| 域 | 成功判据（可执行） | 失败信号 |
|---|---|---|
| permafrost 缓存域 | `bash scripts/claude-ops-deployments/root-scripts/claude-permafrost-rollback.sh status` 显示的当前方案与预期一致；`curl -s http://127.0.0.1:8788/permafrost/stats` 与 `/permafrost/doctor` 均能返回 JSON | status 仍停在原级别；doctor 报 anchor 变化 / `.orig` 缺失 |
| 直连域 | 三处 `ANTHROPIC_BASE_URL` **取值一致**且指向预期端点：`settings.json` · `settings.local.json` · shell 环境（`grep -rn ANTHROPIC_BASE_URL ~/.claude/*.json` 与 `env \| grep ANTHROPIC_BASE_URL`） | 三处不一致（改了配置没改 shell，或反之） |
| cache-relay / 软回滚域 | `curl -s http://127.0.0.1:8790/__relay__/health` 返回 `{relay,pid,port,uptimeSec}`；软回滚时 `~/.cache-relay/.disabled` **存在**，逃生阀时 `RELAY_FORCE_PROVIDER=passthrough` 生效 | health 无响应；`.disabled` 与预期相反 |
| 版本域 | `claude --version` 返回目标版本，且与 `~/.claude/version-switch.log` 末行一致 | 版本未变（软链接未切）或与日志不符 |
| 守护 / 部署域 | 对应 `rollback.sh` 退出码 0，且本次变更已写入 `deployment-log` | 退出码非 0，或日志无记录（**不可审计 = 未完成**） |

> 共同底线（[[AGENTS]] 五·五 部署四规则）：**没有日志记录 = 没有完成**；**没有回滚方案 = 不许部署**。
> 关联复盘：[[claude-cache-incident-postmortem]]（无回滚门禁的代价）· [[claude-proxy-deployment-postmortem]]（逃生通道必须在部署前就绪）。
