## 三、事件 C: `sk-<REDACTED>` DeepSeek Key 异常消耗 (核心问题, 待查)

### 状态: 🔴 这是真正的异常 — ARK 两条 key 都有合理解释, 唯独 sk-<REDACTED> 不该被消费

### 已知事实
- key 存在于 `/home/pi/.claude/settings.local.json` 的 3 处 curl 命令中 (Claude Code 配置)
- key 已被用户销毁
- 用户报告消耗约 150 元 / 5 亿+ token, **集中在 6月28日一天**
- **飞书对话记录中未搜到该 key** — 不是通过飞书泄漏
- **不在 hermes config 中** — 不是通过 hermes 消费

> [!warning] 补（2026-09-13）：「约 150 元 / 5 亿+ token」不可审计，且整节缺对照基线（原表述为上面「已知事实」里的消耗报告与本节判据）
> **① 数字口径缺失**：这条只有总额，**没有模型名、没有 cache hit / miss 拆分、没有计价日期**。按 DeepSeek 现行价目表核对（2026-09-13，<https://api-docs.deepseek.com/quick_start/pricing>）：
>
> | 模型 | cache-hit（空闲 / 峰值） | cache-miss（空闲 / 峰值） |
> |------|--------------------------|---------------------------|
> | `deepseek-flash` | $0.003 / $0.006 | $0.15 / $0.3 |
> | `deepseek-v4-pro` | $0.022 / $0.044 | $0.66 / $1.32 |
>
> 空闲价 = 峰值价的一半；**hit 与 miss 单价相差约 50 倍**。
> ¥150 ÷ 5×10⁸ token ≈ **¥0.3/M（≈ $0.042/M）**的混合单价，反推隐含命中率约为 **flash 74–88%**、**v4-pro ≈ 97%**。因此「只有命中率 >95% 才可能」这一说法**只在按 v4-pro 计价时成立**；按 flash 计价，命中率 75% 上下即可。措辞应改为「**取决于模型与 hit/miss 拆分，对命中率极其敏感**」。
> **② 缺对照基线**：本节把用户单方报告的「异常消耗」直接当作事件 C 的判据，却没有该 key 的历史日均消耗、6-28 前后各 7 天的消耗，以及 hermes / Claude Code 侧的调用次数统计。该补：
>
> | 日期 | 调用次数 | input token | output token | 命中率 | 估算费用 |
> |------|----------|-------------|--------------|--------|----------|
> | 待补 | 待补 | 待补 | 待补 | 待补 | 待补 |
>
> 无法取得时，必须明确写「**用户口头报告，未经账单核对**」——按本库规则，**现象不能当结论**。

## 五、关键教训

1. **`model_router.main()` 的回退机制是根因**: 无 `--api-key` 时静默从 config 读取, 导致 key 替换不可见
2. **systemd 单元应始终显式传参**: 不应依赖 config 回退
3. **hermes 会话预览无脱敏**: `sk-`/`ark-` 模式应自动替换
4. **飞书不是发送 key 的安全通道**: 应通过 SSH 直接编辑配置文件
