# DSH 会话脱敏项目方法论复盘

See also: [[AI-Links-KB-Home]] | [[DSH插件与Hook开发最佳实践]] | [[DSH会话脱敏插件缺陷档案]] | [[CORRECTIONS]] | [[AGENTS]]

> [!abstract] 本文档是什么 —— `dsh-plugin-redact`（原地改写 DSH 会话日志、不可再生数据）从"自己测全绿"到"被独立红队打穿 5 个数据丢失级缺陷"再到定稿的**过程复盘**。焦点不是缺陷本身（见 [[DSH会话脱敏插件缺陷档案]]），而是**方法论**：我们的验证在哪里失效、哪些直觉被测量推翻、委派什么有效什么有害、文档为什么返工三次。
> 结论先给：**这个项目里每一次"我觉得没问题"都被测量纠正过，而每一次"套件全绿"都没有提供过任何保证。** 唯一可靠的判据来自被改写的那个系统本身。

> [!danger] 与 [[CORRECTIONS]] 同源 —— [[CORRECTIONS]] 已把同一批工作录入 **C-005~C-011**（发生现场就是本项目），更早的 C-001~C-004 也共享同一根源「**把观察到的现象直接当成结论**」。
> 本项目每一次判断失误都能落到具体条目上（逐条对应见文末对照表）——**它们缺的都是"现象 → 结论"中间那一步判定**，只是各自缺的不是同一步。

## 一、绿色的套件什么都没证明

### 1.1 事实

定稿前的基线是**三套全绿**：`handler.selftest.mjs` **159/159**、`bugfix-regression.mjs` **48/48**、引擎 CLI 套件 **34/34**（红队报告 `docs/reports/redteam/REPORT-zh.md:14-18`）。红队在同一个修订上找出 **5 个数据丢失级缺陷**，其中两个让会话永久打不开，而工具全程报告成功——**全部从这 241 条绿色断言中间溜了过去**。

### 1.2 为什么

`bugfix-regression.mjs` 的夹具**不是读取端合法日志**：它在第 30/142 行把 tool/result 消息写成 `{ role:'tool', source:{ callId:'aa' } }`。真实形状是 `role:'user'` + `source:{ kind:'tool', callId }`（`dsh-llm/lib/types/message.d.ts:22-25`），真实校验直接拒绝：

```
SessionPersistenceCorruptionError: stored session ... failed validation:
  Error: session event at seq 4 message must have role "user"
  Error: session event at seq 4 message has invalid source
```

（`REPORT-zh.md:20-32`）

也就是说：**那 159 条断言扫的是一个 DSH 根本打不开的文件**。而两个不可逆缺陷（`sourceEventSeqs` 游程未重映射、`session/title.messageSeqs` 悬空）恰好只在这片盲区里显形——它们既不是"JSON 不合法"也不是"seq 不连续"，而是**读取端语义**层面的错误：工具的 `applyPlan` 自检只看"JSON 可解析 + 头部 + seq 密集"，看不见这一层（`REPORT-zh.md:51`）。

> [!bug] 更刺眼的一处
> `bugfix-regression.mjs` 里原本有一条断言写着"`hide` 保持 tool 消息结构"，判据是 `role === 'tool'`——**那正是被测代码之外的一个假前提**。断言本身在替缺陷背书：它把"读取端会拒绝的形状"固化成"必须保持的形状"（`docs/reports/fix/REPORT-FIX-zh.md:337`）。

### 1.3 纠正：真实读取端才是判据

修复阶段的硬性要求写在报告第 4 行：判据是 `JsonlSessionPersistence.open()`、`dsh-session` 的 `Session`、`dsh-session-format-catalog` 的编解码器、`dsh-session-title` 的真实不变式——**没有把引擎自己的自检当作"DSH 打得开"的证据**（`REPORT-FIX-zh.md:4`）。落地成三件东西：

1. `test/real-reader.mjs`（新增）：用**真实** `Session` + 编解码器造夹具，用**真实**后端判定"打不开"；找不到真实 DSH 包时**抛错而不是跳过**（`packages/dsh-plugin-redact/test/real-reader.mjs:32-41`）。
2. **夹具本身必须先被真实后端打开才算数**（`bugfix-regression.mjs:92-97`："★ 夹具：改写前 DSH 真实后端可打开（读取端合法）"）。
3. 元发现本身被固化成断言（`hardening.mjs` 第 0 节）："★ 旧夹具形状被真实读取端拒绝 —— `session event at seq 2 lacks an identified message`" 与 "★ 真实形状的同类夹具可以打开 —— 7 events"。

### 1.4 可复用的规则

> [!important] 三条规则
> 1. **判据必须来自被改写的那个系统。** 自检的语义上限就是"我实现了什么"，它永远无法证明"对方接受什么"。
> 2. **同一个人写的自检不构成独立证据。** 作者与代码共享同一套误解；自检只会重复那套误解（这正是 C-003 的形状：扫描器是瞎的，却把 0 命中读成干净）。
> 3. **夹具必须先被"对方"接受，再拿去测自己的代码。** 一句 `assert(fixtureOpen.ok)` 就能把整条盲区封死——本项目的这一个断言，比之前 241 条都值钱。

## 二、被测量推翻的"直觉"清单

以下每一条都是**先有直觉、后被测量否证**。列出来是因为它们的形状高度可复用：**直觉都指向"这是安全的"，测量都指向"这不是"。**

### 2.1 "删除一行是安全的" ❌

seq 密集约束（每行 `seq === 行号-1`）让**删中间任意一行 = 整份日志打不开**。读取端逐行累加并断言 `event.seq === eventCount`。工具因此把主力手段定为三种**原地改写**（行数/`seq`/`type` 全部不变），删除只在末尾后缀上安全；删中间行必须显式 `renumber: true`，遇到悬空引用仍拒绝（`README.zh.md:36-55`，拒绝理由同时给出三条出路）。

### 2.2 "多行通知会渲染成多行" ❌

渲染端 `cleanRenderText(text, COMMAND_RESULT_CELLS = 200)` 把 `\n`、`\t`、连续空格**全部压成一个空格**，再按 200 显示格截断（CJK 算 2 格，中文实际只有约 100 字的位置）。这是硬约束、不是风格选择（`README.zh.md:236-254` 贴出了渲染端实现）。后果：所有面向用户的输出必须"短 + 重要信息在前"，插件干脆在离开 handler 前自己先 `clamp` 一遍（`packages/dsh-plugin-redact/index.js:41-52`）。**一条"设计给多行看"的报错，尾巴会被静默砍掉**——`apply` 拒绝文案里那条 `--allow-live` 出路就曾经被砍在半路（`docs/reports/fix/after/handler.txt` 观察 F）。

### 2.3 "`--dump-config` 证明插件能加载" ❌

`--dump-config` **根本不 import 模块**：它只合成配置层。启动扫描实测，`--dump-config` 会显示那一行，而同一行在真实启动时可以把整个 profile 拉下来（`dsh: plugin tree failed to load: … failed to import loader entry …`）。证据：`docs/reports/boot-verify/out-throwImport.json`、`sweep3.txt:13-21`（`throwImport`/`badConfig`/`badApply`/`dupRules`/`redactBadShape` 全部 `BOOT_ABORTED`）。→ **验证插件必须真的 boot 一次**，这也是 `probe.mjs` 存在的理由（它走的是 `dsh-app-boot` 的真实 `boot()` 路径，`probe.mjs:8-10`）。

### 2.4 "用条件 `disabled` 让插件自动二选一" ❌

想法：用 `!!js` 表达式让 redact 行在"没有 `tuiDialogs` 提供者"时自动禁用，这样既能硬依赖服务、又能在非 TUI profile 上优雅降级。实测**行不通**：`Entry.disabled` 是**实时 getter**，判据会随挂载进度翻转，结果是**整个 boot 中止**；对照场景里 `guardNoProvider` 稳定 `BOOT_ABORTED`、`guardProviderBefore/After` 也只在一侧成立（`docs/reports/boot-verify/probe.mjs:128-155`、`sweep5.txt:8-16`、`stable.txt:3-7`）。结论写进了包的补丁文件注释："**不要**用 `!!js` 的 `disabled` 自禁用守卫来自动二选一"（`README.zh.md:170`）。

### 2.5 "服务存在 ⇒ 对话框会渲染" ❌

这是本项目最贵的一条，也是最像 C-002 的一条（把"可达"当成"可用"）。契约核对证明 `ctx.get('tuiDialogs')` **可达性有保证**（同一 root、同 registry、实测拿到 `select/confirm/input`），但**准入是条件性的**：调用方必须是本 composition 中"已登记在册的活跃非 root 激活"，若本行早于第一个安装 composition-root tracker 的 TUI 适配器模块进入 ACTIVE，每次调用只写一条 logger warning 就返回取消值——**面板根本不弹**（`docs/reports/dialog-contract/REPORT.zh.md:13`、`:64-78`）。更根本的是渲染层：`Chat.js:3585` 的提示槽里 `approvalPanelNode` **无提示压掉** `ExtensionDialog`，而 `Chat.js:2566` 已经让出键盘 → "active 但不可见、不可应答"；ApprovalStore 又没有超时，于是这是**稳态**而非窗口（`docs/reports/dialog-root-cause/ROOT-CAUSE.zh.md:44-57`、`:186-191`）。

> [!quote] 根因报告的一句话
> "冻结不是插件的 bug，是「把 promise 停在一个不保证被渲染的 FIFO 里」这件事的必然代价；唯二的安全做法是**别把 promise 停进去**。"（`ROOT-CAUSE.zh.md:310`）

响应不是"加个探测"——报告专门论证了**可靠的前置检查不存在**（即使拿到 `listeners.size` 也没用，Chat 恒定订阅；且渲染时刻求值意味着 TOCTOU 竞态无法关闭，`ROOT-CAUSE.zh.md:202-226`），而是**换机制**：`nodes` + `hide <序号> --commit` 两次同步命令，`pick` 默认关闭。

## 三、爆炸半径思维：为什么"一行挂不上"是全局问题

### 3.1 事实

DSH 的启动器把"任何一行 FAILED / 永远 PENDING"升级为**致命错误**——不是"该插件不可用"，是**整个 profile 起不来**。启动扫描把这条做成了一张表：`throwImport`/`throwApply`/`missing`/`pending`/`badConfig`/`badApply`/`dupRules`/`redactBadShape` 八种场景全部以 `dsh: plugin tree failed to load` 结束（`docs/reports/boot-verify/sweep3.txt:13-21`、`sweep5.txt:17-25`）。

### 3.2 它改变了什么

| 面向 | 天真做法 | 爆炸半径下的正确做法 |
|---|---|---|
| import 面 | 随手 `import` 需要的模块 | **零依赖**：只 import `node:crypto` 与自己的 `lib/scrub.mjs`；`@deepseek-ai/*` 只是 optional peer，不装也不会在 import 阶段失败（`packages/dsh-plugin-content-policy/README.zh.md:359-361`） |
| 配置校验 | 校验失败就打日志、用默认值继续 | **响亮失败 + 精确报错**：错误文案带字段路径，报错点紧贴加载这一行 |
| 空/缺配置 | 非对象一律当错误 | YAML 留空是 `null`（**不是** `undefined`）→ 视同 `{}` 用默认值；否则一个空 `config:` 会中止整个 profile 的启动（`packages/dsh-plugin-redact/index.js:559`、`:565-567`） |
| 未知键 | 报错拒绝 | **只告警不拒绝**（与平台自身的 config 语义一致）：不能让一个手滑的键名打断启动（`index.js:605-611`） |
| 硬依赖服务 | 想要就写进 `inject` | 写进 `inject` 的代价是：服务缺席时本行永远 PENDING → **整个 profile 起不来**。所以默认层不写，只在确实用面板时由 `cordis.patch.tui.yml` 加行级 `inject`（`README.zh.md:190-192`） |

### 3.3 为什么选"响亮失败"而不是"静默降级"

> [!important] 判据是**谁来承担后果**
> 静默降级把"插件没生效"变成"用户以为脱敏在跑"——在一个改写不可再生数据的工具上，这是**最坏的失败模式**：用户据此不再采取别的措施。所以凡是"读取端会拒绝的输出"，一律**挡在写盘之前**并 `die()`（`lib/engine.mjs:337` 的 `verifyLog` 总闸）；凡是配置必然导致行为不可预期，一律在 `apply()` 里同步抛错，宁可不注册命令（早失败 = 早看见，`index.js:562-563`）。
>
> 反过来，**不影响用户判断的东西一律不降级成失败**：缓存清理失败并入成功文案（`已脱敏 … · 缓存清理 0`）、未知配置键只告警。判定线是"这件事会不会让用户对'数据已经不在了'产生错误认知"。

## 四、委派：什么有效，什么有害

### 4.1 有效的部分

> [!success] 三条真正付了钱的委派
> 1. **独立、只读授权的审查者能找到作者测试找不到的缺陷。** 红队的授权是"只读 + 合成数据 + 真实编解码器"，产出 5 个数据丢失级缺陷，且每条都带**可重复执行的复现脚本**（`p1-refs.mjs` … `p8-structural.mjs`）。它能成功的关键不是更聪明，而是**没有被作者的自检说服**——它把真实读取端当判据。
> 2. **对破坏性工具的对抗性审查，投入产出比极高。** 工具改的是不可再生数据；一次红队审查换来的是"数据丢失类缺陷归零 + 一套 78 条的回归套件"（`hardening.mjs`，判据是真实读取端）。
> 3. **写清"什么能证伪我"比"请检查一下"产出的报告好一个量级。** 红队报告有专门一节列出**攻过但没打穿**的部分与原因（`REPORT-zh.md:242-282`）：例如 `purgeCache` 的删除半径打不穿（比较对象是 `readdirSync` 的目录项名，不可能含路径分隔符）、`rollback` 的边界逻辑全部正确、毫秒级备份名碰撞在 40 次连跑 + 8 轮双进程并发下**没有复现**，因此**只记为潜在风险、不列为已证实缺陷**（`:253-257`）。**"我没打穿"和"这里没问题"是两句话**——这份报告把它们分开了，这是它可信的原因。

### 4.2 有害的部分

> [!bug] 并发编辑：文档与测试在追一个移动的修订
> **实测证据（同一份扫描的前后哈希）**：`docs/reports/boot-verify/` 下五次扫描的 `===== BEFORE =====` 区段记下了被测 `index.js` 的 sha256 前 16 位：
>
> | 扫描 | `dsh-plugin-redact/index.js` | `lib/engine.mjs` | `dsh-plugin-content-policy/index.js` |
> |---|---|---|---|
> | `sweep.txt` | `7d4c28d67e532bdc` | `7305d5efec83a7be` | `9371dd47f3c726cd` |
> | `sweep2.txt` | `7d4c28d67e532bdc` | `7305d5efec83a7be` | `0e21b9ef9426a661` |
> | `sweep3.txt` | `dd21d56e6bf31dd6` | `1ea235d3d36b0ff9` | `0e21b9ef9426a661` |
> | `sweep4.txt` | `3d92f8eedb50a9f0` | `1ea235d3d36b0ff9` | `375387bc155d96c6` |
> | `sweep5.txt` | `cefe723fea361d2a` → `f9baf926748d795a` | `1ea235d3d36b0ff9` | `375387bc155d96c6` |
>
> `index.js` 在**五次扫描之间换了五个哈希**；`engine.mjs` 换了一次；content-policy 换了两次。同一个工具不得不为此写了一版**重试到"整轮修订不变"才承认结果**的驱动：`stable.mjs` 的 `while (attempt < 6 && !stable)`，输出末尾必须打印 `STABLE: revision unchanged across the whole run` 才算数（`docs/reports/boot-verify/stable.mjs:50-65`、`stable.txt:25`）。
>
> 代价具体是什么：
> - **报告的行号当场作废。** 对话框根因报告开头就写着"⚠️ 调查过程中 `dsh-plugin-redact/index.js` 被并发修改（1164 行 → 1168 行）。本文引用的插件行号以最后一次读取为准"（`ROOT-CAUSE.zh.md:15`）。
> - **两次核对的哈希对不上。** 契约核对报告记录的 `index.js` 是 `sha256 C69599C1…`、53112 B，并注明"该文件在核对期间被改过两次：52931→53112"（`dialog-contract/REPORT.zh.md:4`）。
> - **接手的人无法复跑旧数字。** 修复报告坦白："唯一的例外：F7 的 before 数字来自红队报告的实测值——我接手时磁盘上只有修复后的 `engine.mjs`（没有 git、没有旧副本），无法重跑旧代码"（`REPORT-FIX-zh.md:61`）。**没有版本控制 + 并发编辑 = 一半的 before/after 永远无法复核。**

> [!bug] 一处被后续验证推翻的产物，只能存档
> 修复报告 §5/§6 明确划出几处"我故意没做/没证明"的边界，其中两条是**产物与后续验证相矛盾**的典型：
> 1. **`p4-write.mjs` 的 A/B 段在修复后依然 PASS**——因为它演示的是**旧顺序的 syscall 序列（手工复刻），不是在调用当前代码**。修复报告专门声明："它们仍然是「旧顺序有害」的演示，但**不能**作为「新顺序正确」的证据——后者由 `hardening.mjs` 的注入式 F4 断言承担。这一点我在表格里写明了，免得后人误读"（`REPORT-FIX-zh.md:193`、`:353`）。**处理方式是存档 + 标注，不是删除、也不是拿去当证据。**
> 2. **`p5-rollback.mjs` 剩下 1 条 FAIL 不是缺陷**：断言期望 `共 2 个完整轮次`，而 handler 一直打印 `共 2 轮`——**红队自己写错了正则**（`REPORT-FIX-zh.md:350`，红队报告 §2.2 亦自述）。修复方**没有为了让它变绿去改文案或改脚本**（`:350`）。
>
> 这两条与 [[CORRECTIONS#C-004 转述未回溯原始来源]] 是同一类：**产物会衰减**。处理规则是"标注它到底证明了什么、没证明什么"，而不是让它继续以"绿的"身份流通。

### 4.3 一条更省事的替代方案

对不可逆工具，"独立审查"的**最小可行动作**其实很便宜：**把判据换成对方的实现**（真实读取端 / 真实注册表 / 真实不变式），再找一个没写过这段代码的人（或代理）去构造反例。本项目 78 条 hardening 断言里，真正有价值的部分全是这个形状。

## 五、文档返工：三次，都在追同一个移动的修订

### 5.1 事实

知识库这一侧的文档**改写了三次**，每次都是因为被测代码又动了：

| 轮次 | 触发 | 后果 |
|---|---|---|
| 第一轮 | 按功能写"它做什么" | 代码大改后**行为描述整体过期**（默认值、输出文案、子命令语义） |
| 第二轮 | 按缺陷写"修了什么" | 修复期间代码仍在移动（`index.js` 五个哈希），**行号与字节数全部漂移** |
| 第三轮 | 冻结代码后重写 | 才有"实跑输出逐字粘贴 + 最终断言计数" |

### 5.2 采用的补救（已落地，可直接抄）

> [!important] 四条规矩
> 1. **先冻结代码，再写文档。** 中间态不写"定稿文档"。补救手段是给验证加**哈希包夹**：`sweep.mjs` 在整轮扫描前后各打印一次被测文件的 sha256，只有前后一致才承认结果（`docs/reports/boot-verify/sweep.mjs:19-23`、`:36`）；`stable.mjs` 更进一步，**不一致就整轮重跑**（最多 6 次）。
> 2. **输出字符串逐字来自一次实跑，不凭记忆写。** 文档里的每条命令输出都必须能在存档里找到出处（`docs/reports/fix/after/*.txt` 与 `baseline/*.txt` 每脚本一份）。凡是"我记得它大概会打印…"的，一律不算。
> 3. **计数放在最后一次测试跑之后。** 断言条数是**结果**不是**输入**：各套件实测 `248/248`、`54/54`、`78/78`、`34/34`、content-policy 四套 `45+36+17+5`。中途写入的任何计数都注定要返工。
> 4. **把"通过的到底是哪一版"写进输出。** `handler.selftest.mjs` 自报被测文件的**字节数与 sha256 前 12 位**（`test/handler.selftest.mjs:83`）——报告里的数字因此可追溯，也让"文档 vs 代码漂移"从"看不出来"变成"一眼可见"。

### 5.3 一条副作用检查

三次返工里最容易被忽略的是**交叉引用**：文档改了行为描述，别的文档里的示例命令与默认值也要跟着改。本项目的教训是——**默认值（`dialogTimeoutMs` 从 120000 改成 15000、`pick` 默认关闭）是跨文档出现频率最高、也最容易漏改的一类事实**，必须集中在一处定义、其余地方引用。

## 六、一个改写不可再生数据的工具，欠用户什么

这不是"最佳实践清单"，而是**这个工具的失败模式决定了它必须有的东西**。每一条都对应缺陷档案里的实际缺陷：
| 义务 | 为什么（对应缺陷） | 本项目的落地 |
|---|---|---|
| **默认 dry-run** | 用户必须先看到"要改哪几行、删几条、帧怎么变"，再决定动手 | `plan` / `rollback` / `undo` / `hide` 默认只试算；写盘一律要显式 `--commit`。实测输出：`试算 OK（未写盘） · <id8> · 行 删0/空1/改1/换1 · 帧 留1/写2 · 自检通过` |
| **隔离备份（quarantine）** | 数据不可再生，任何"就地改写"都必须有可回退点 | 就地替换前先写 `*.quarantine-<时间戳>`；成功文案把备份名与"**仍含原文，确认无误后自行删除**"放在**最前**（渲染端只保留前 200 格，放后面等于没写） |
| **拒绝优于猜测** | 写出悬空引用的"成功"比"拒绝执行"坏得多 | 引用字段做成**显式清单 + 失败关闭审计**：清单外的 `*Seq` 字段一律拒绝并报出路径（`lib/engine.mjs:225-240`）；下游会拒绝的输出挡在写盘前（`verifyLog` 总闸，`lib/engine.mjs:337`）。**另加**：多目标中途失败时如实报出"已经改掉的那部分"（`已有 1 个节点被永久遮蔽（seq 1），该变更已生效且不可撤销`），而"假的可提交性预检"被明确拒绝实现——`session.append` 的失败源无法在不提交的前提下预判（`REPORT-FIX-zh.md:364`） |
| **明说自己做不到什么** | 用户会把"工具没报错"读成"内容已经不在了" | README 有独立一节"局限（诚实清单）"，23 条，包括"已经离开本机的内容收不回来"、"`hide` 不是脱敏"、"隔离备份仍含原文"、"只处理版本号最高的那一份日志"、"清单文件不会自动清理"（`README.zh.md:603-627`） |
| **绝不打印它正在删除的内容** | 脱敏工具的输出本身会变成新的泄漏面（终端回滚、日志、命令历史、截图） | 全链路只输出**行号与计数**：`scan … 命中 2 行：2,5 · 未改动任何文件`、`nodes` 只给"序号/行号/轮次/工具/体积"，**工具结果正文永远不显示**；命令注册设 `recordInput: false` 让匹配串不进日志；匹配文本必须写在计划文件里而不是命令行上（`README.zh.md:282`、`:296`、`:330`） |

> [!warning] 还有一条容易被漏掉的义务：**如实报告半途状态** —— 见上表"拒绝优于猜测"一行的补充：多目标操作中途失败时，"已经改掉的那部分"必须告诉用户；而做一个"假的可提交性预检"是**有害的**，它只会制造虚假的安全感。

## 七、给下一个在这套平台上动手的人的检查清单

> [!tip] 动手前
> - [ ] **读读取端源码，不读文档。** 日志是"独立校验和 zstd 帧的拼接"、`seq` 必须密集、引用字段在盘上可能是 `[start,end]` 游程——这些都没写在文档里（`README.zh.md:556-560`）。
> - [ ] **先问"这一行挂不上会怎样"。** 答案是整个 profile 起不来。据此决定 import 面、配置校验与 `inject` 的严格程度；并**别信 `--dump-config`**（它不 import 模块），验证插件必须真的 boot 一次（`docs/reports/boot-verify/probe.mjs`）。
> - [ ] **在真实前端里试一次交互路径。** "服务可达"不等于"面板会渲染"（`dialog-contract/REPORT.zh.md:13`）。

> [!tip] 写代码时
> - [ ] **判据用对方的实现**：真实 `JsonlSessionPersistence.open()`、真实注册表、真实不变式。自检只用来"挡在写盘之前"，不能用来宣布成功。
> - [ ] **夹具先过对方的校验**，再加一句断言把它钉死（`★ 夹具：改写前 DSH 真实后端可打开`）。
> - [ ] **引用清单要显式，并失败关闭**：凡键名以 `seq`/`seqs` 结尾却不在清单里 → 拒绝（注意驼峰：`/(^|_)(seq|seqs)$/i` 这种正则一个都匹配不到）。
> - [ ] **写序：先截断后写**；写前复查修订号；校验累计写入字节数；写完复查文件长度；`fsync` 文件与目录。
> - [ ] **绝不 `process.exit`**——插件跑在宿主进程里。抛类型化错误，让调用方决定。
> - [ ] **空 `config:` = `null`**，视同 `{}`；未知键只告警；数值字段在 `apply()` 里同步校验（早失败 = 早看见）。
> - [ ] **输出按 200 显示格设计**（CJK 算 2 格）：单行、关键信息在前、宁可少列几条也不让行号被截断。

> [!tip] 交付前
> - [ ] **`npm test` 在干净机器上真的跑得起来**；跑不了的套件必须**非零退出**（不是"跳过 + exit 0"）。
> - [ ] **LICENSE 落成文件**并进 `files`；`scripts.test` 写进 manifest；**把作者的绝对路径从测试与产物里清掉**。
> - [ ] **冻结代码再写文档**；报告里贴的每条输出都来自一次可定位的实跑；计数放在最后一次测试跑之后。
> - [ ] **验证脚本自己做哈希包夹**（整轮修订不变才承认结果），并把"我没证明什么"一并写进报告（本项目：live 写入 syscall 中途被打断的窗口没关；短写循环只有代码级保证；`purgeCache` 的失败分支没在 Windows 上真实触发过）。

## 八、与 [[CORRECTIONS]] 的逐条对应

[[CORRECTIONS]] 已把同一批工作录入 **C-005~C-011**，发生现场就是本项目。加上更早、但同根源的 C-001~C-004，本项目每一次判断失误都能落到具体条目上——**这不是巧合**：它们共享同一根源「**把观察到的现象直接当成结论**」，只是各自缺了不同的那一步判定。

| CORRECTIONS 条目 | 本项目里的同构表现 | 缺掉的那一步 |
|---|---|---|
| [[CORRECTIONS#C-001 只读漏洞公告的一半]] | 只读到"引擎自检通过"就停手 | 没追问下一个值 → 没问"读取端打得开吗" |
| [[CORRECTIONS#C-002 把可达性外推为可被利用]] | 服务可达被当成面板会渲染 | 没验证"调用 → 效果可见"的整条链 |
| [[CORRECTIONS#C-003 信任未经校准的扫描结果]] | 夹具不合法 → 159 条断言扫的是打不开的文件；套件跑不了却 `exit 0` | 没证明"扫描器看得见目标" → 没证明"测试真的跑了" |
| [[CORRECTIONS#C-004 转述未回溯原始来源]] | `p4-write` 的旧 syscall 演示被当成"新顺序正确"的证据 | 没回溯产物证明的到底是什么 |
| [[CORRECTIONS#C-005 拿工具自检当读取端验收]] | 第 1 节全部内容 | 自检的语义上限是"我实现了什么" |
| [[CORRECTIONS#C-006 假设渲染行为而不读渲染端]] | 第 2.2 条（多行通知） | 没找到并读消费这段文本的那个函数 |
| [[CORRECTIONS#C-007 拿配置组合当运行时证明]] | 第 2.3 条（`--dump-config`） | 没走完"组合 → import → apply → ACTIVE" |
| [[CORRECTIONS#C-008 拿绿色测试当可用性证据]] | 第 1 节 | 没问"这套测试会漏掉什么、夹具与真实产物同形吗" |

> [!important] 本项目的总结论，只有一句 —— **现象 →（一步判定）→ 结论。** 这篇复盘里所有被推翻的假设（第 2 节五条）、所有漏过的缺陷（第 1 节）、所有返工（第 5 节），缺的都是中间那一步。而唯一稳定有效的补救也很朴素：**把判据换成对方的实现，并且先证明这个判据看得见目标。**
